# 04 — H3 Motion Context：用「真续接」取代「融合掩盖」

来源：大圣 Ai 自习室（2026-11-04）的「无缝延长」教程 + [NikoDemon80/ComfyUI-H3-Motion-Context](https://github.com/NikoDemon80/ComfyUI-H3-Motion-Context) 官方文档。

## 为什么做这个

我们现在的接缝处理是**掩盖**：两段独立生成，拼接时把前 6 帧和后一段的头 6 帧加权溶解。实测切点跳变 22.17 → 6.35，但本质上仍是两段不相干的画面被强行过渡。

Motion Context 是**真续接**：把上一段的 latent 尾部（画面+声音）钉在新一段的开头，模型从这个状态往下生成，然后把这几十帧裁掉。接缝处前后是同一段连续画面，不存在跳变。

**关键优势（官方文档原话）**：它从 latent 直接切片，不经过像素往返，所以没有解码→缩放→重编码带来的色偏和软化。我们的 6 帧融合恰恰是在像素域做的。

## 机器上已有

```
ComfyUI\custom_nodes\ComfyUI-H3-Motion-Context.disabled
```

已安装但被禁用。ComfyUI 0.43.0 满足它要求的 ≥0.34.0。

## 节点链

```
MiniMaxH3ReferenceToVideo（肖像 + 本句配音）
  → H3 Motion Context（context_latent = 上一段的 latent）
  → PixaromaH3AudioSync
  → KSampler
  → H3 Motion Context Trim（trim_frames）
  → VAEDecode / VAEDecodeAudio
```

跨 run 传递 latent：
```
上一段：SamplerCustomAdvanced → H3 Motion Context Save Latent（clip_index=1）
本段：  H3 Motion Context Load Latent（clip_index=1）→ context_latent
```

## 官方推荐参数

| 参数 | 值 | 说明 |
|---|---|---|
| `context_length` | **22 帧** | 可选 5/22/39/56。22「几乎无缝」，56 要扔掉 2.3 秒 |
| `audio_context_length` | **18 帧** | 与画面窗口同时结束，只控制声音回溯多远 |
| `match_tail`（Trim） | **开** | H3 音频栅格每次约有 8ms 误差，会逐段累积 |

## 三个变体（按成本排序）

### 04A — 纯诊断：Seam Probe

包自带 `Seam Probe` 节点，判断一次拼接是「真延续」还是「像样的模仿」。

- **做法**：拿现有成片的相邻两段，跑一次 probe，得到量化判据
- **成本**：5 分钟，不需要重新渲染
- **产出**：一个基线数字，后面所有改动都对着它比

### 04B — 单接缝对照（核心实验）

- **做法**：L01 正常生成 → L02 带 22 帧上下文生成 → Trim 22 帧 → 与 L01 拼接
- **对照**：同样的 L01/L02 用现有方法（独立生成 + 6 帧融合）
- **量什么**：切点帧间差、身份相似度、画面是否漂移
- **成本**：约 25 分钟（L01 已有可复用，只需重渲 L02 ≈ 10 分钟 + 拼接）

### 04C — 三链接力（验证累积误差）

- **做法**：L01→L02→L03 连续三次带上下文生成
- **为什么**：官方文档明确说「长链会漂移，脸会变精致或变老，色彩逐段偏移」，三个实验节点只能减轻不能消除
- **成本**：约 35 分钟

| 指标 | 现方案 | 目标 |

| 身份 sim 变化 | 0.76–0.83 | 不劣于 |

## 风险

| 风险 | 应对 |
|---|---|
| 我们的音频是**逐句独立 TTS**，而包的设计是连续音频轨 | 钉住的 22 帧会带上一段的音频尾巴；裁掉后交付的是本句音频。**需要实测确认模型是否把本句音频接在钉住段之后** |
| 分辨率必须两段一致 | 我们全是 1600×928，满足 |
| Chain 节点要求 Load/Save/Chain 在同一个 canvas group | 我们用脚本调用，不走 UI，不受影响 |
| 节点在 0.43.0 上可能有布局校验失败 | 首次调用会打印校验结果，失败会明确报错而不是出坏片 |

## 实测结果

单接缝对照（L02 → L03，896×512，8 步，Sage，同 seed）：

| 方案 | 切点跳变 | 相对段内正常运动 | 音频完整 |
|---|---|---|---|
| 无上下文，无融合 | 23.97 | 20× | ✅ |
| 无上下文 + 6 帧融合（**当前生产**） | 6.59 | 13.7× | ✅ |
| Motion Context，无融合 | 6.50 | 4.7× | ❌ |
| Motion Context + 融合（未补静音） | 1.84 | 1.3× | ❌ 丢开头两字 |
| **Motion Context + 融合 + 补静音** | **2.46** | **1.8×** | ✅ |

**结论：可用，切点跳变 6.59 → 2.46（−63%），代价 +20% 渲染时间。**

## 两个必须知道的坑

### 坑 1：拼接的人脸对齐会毁掉连续性

`join_clips.py` 的人脸对齐是为「独立生成、构图不同」的片段设计的。片段已经是真续接时，
两段本来就对齐，再 warp 一次反而制造跳变：

```
原始片段边界   5.75
经过人脸对齐   21.30   ← 比不做上下文还差
关闭对齐       6.50
```

所以续接模式下必须 `JC_ALIGN=0`。

### 坑 2：逐句 TTS 要前置静音

Motion Context 钉住的 22 帧会在新片段开头，生成后要裁掉。我们的配音是逐句独立的，
模型把本句音频从第 0 帧就开始生成，裁剪直接吃掉开头：

```
未补静音转写：  "一台普通的电脑 学会说话"        ← 少了「怎么让」
补 0.92s 静音： "怎么让一台普通的电脑 学会说话"  ← 完整
```

做法：生成前给 wav 前面加 `context_length / 24` 秒静音（22 帧 = 0.92 秒）。
